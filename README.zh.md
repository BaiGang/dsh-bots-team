# DSH Bot Team

在 [DeepSeek Harness](https://github.com/deepseek-ai) 左侧栏里放一支 AI 机器人团队。
每个机器人都是一个真实的 DSH 会话，拥有自己的文件夹、自己的人格设定和独立的对话——像给联系人发消息一样和它说话，不用在会话列表里翻找。

## 可以照着组的团队

不必从零设计名册。下面两个组合直接可用，聊过一轮之后再按需改成自己的。

**研究桌** —— 输入一篇论文或一个实验，输出一个有依据的判断：

| 机器人 | 角色 | 可以直接粘的人格 |
|---|---|---|
| Reviewer | 审稿人 | 像一个严厉但公正的审稿人：结论有证据支撑吗？基线公平吗？什么结果能证伪它？ |
| Replicator | 实验复现 | 在你的文件夹里用现有数据重跑方法，明确说明哪些复现了、哪些没有，并给出能证明的命令。 |
| Librarian | 论文检索 | 找相关工作、读掉它、返回带链接的短简报：什么新、哪里有争议、接下来该读什么。 |

**交付桌** —— 代码与运维：

| 机器人 | 角色 | 可以直接粘的人格 |
|---|---|---|
| Builder | 实现 | 写最小的可用改动，跑起来，并报告能证明它的那条命令。 |
| Reviewer | 评审 | 上线前读 diff：正确性、本可提前抓住这个 bug 的测试、任何会破坏调用方的地方。 |
| Operator | 运维 | 盯着正在跑的东西，从日志复现故障，交回一个修复或一个精确的问题。 |

在面板里建（**新建机器人**，填角色和人设），或者直接在对话里说：*"雇一个像严厉审稿人那样读稿的机器人，再雇一个只返回带链接简报的文献机器人"*。名字、图标、角色都随你——真正被遵循的是人格，而人格随时可以重写。

## 为什么是这样

DSH 本来就很会跑 agent；消息应用形状的团队补的是"把它们放在哪里"：每个机器人有稳定的身份（名字、图标、角色）、稳定的工作文件夹、稳定的对话，一键就能找到。

面板本身不是另一套运行时，而是架在真实会话上的消息层。在这里发消息调用的是 `session.prompt()`——和输入框完全同一条路径——所以回复既流进面板，也留在机器人自己的会话里；点**打开完整对话**就回到 DSH 原生界面（工具、审批、文件、终端全在）。

## 每个机器人有自己的文件夹，文件夹就是人格

创建机器人时，Host 半把它的指令写进 `<机器人文件夹>/AGENTS.md`。DSH 自带的 workspace instruction loader 会为在该文件夹里启动的每个会话载入这个文件，因此：

- 人格走的是受支持的机制，而不是私有的提示词 hack；
- 重启不丢，可以直接读、直接改、可以做 diff；
- 每个机器人文件夹里有一个 `.git` 标记，使这个文件夹成为自己的指令根，上层目录的说明不会渗进来。

## 能力

- **左侧栏入口** —— 和其他面板并列的全局面板图标（两个机器人头像），同一个 id 打开主栏里的团队页。
- **名册** —— 头像、名字、角色、正在工作/空闲的实时状态点；面板打开时会自动刷新，别处新雇的机器人也会出现。
- **每个机器人一个对话** —— 对话记录、工具调用小标签、工作中指示、输入框；发送的消息进入和原生聊天同一个会话。
- **第一条消息启动机器人** —— 会话在该机器人文件夹里按需创建、绑定到名册、然后发送消息，所以它的指令在开口前就已载入。
- **角色模板** —— Scout（研究员）、Forge（工程师）、Ledger（分析师）、Quill（写作者）；首次运行会雇好前三个。
- **代理工具** —— 同一份名册，agent 也能改。
- **中英双语界面** —— 跟随 DSH 的界面语言。

## 安装

需要带 Web 界面的 DSH profile（面板是浏览器插件），DSH 版本 `0.2.x` 及以上。

```sh
git clone https://github.com/BaiGang/dsh-bots-team.git
```

在 DSH 里打开 **插件 → 添加插件**，选择克隆下来的目录。bundle 会立即激活；随后刷新页面，让新的浏览器 bundle 进入启动图，左侧栏就会出现 **团队**。

插件行支持一个可选配置：

```yaml
- id: bots-team
  name: 'dsh-bots-team'
  config:
    dataDir: /absolute/path/to/team-data   # 默认：$DSH_HOME/bots-team
```

## 使用

1. 点左侧栏的 **团队**。
2. 选一个机器人，或点 **新建机器人** 从角色模板开始。
3. 输入消息。第一条消息会在它自己的文件夹里创建会话；之后的消息继续同一个对话。
4. **打开完整对话** 会在主栏切换到该会话。
5. **编辑** 可以改名、换图标、改角色或指令；指令会重写进 `AGENTS.md`，下一条消息生效。

## 代理工具

| 工具 | 作用 |
|---|---|
| `team_roster` | 列出每个机器人的角色、人格、文件夹，以及是否已有会话。 |
| `team_hire` | 按名字、角色、人格、图标新增一个机器人，并写好它的文件夹。 |
| `team_brief` | 重写某个机器人的人格或角色。 |
| `team_fire` | 把机器人移出名册；文件夹和会话保留在磁盘上。 |

所以在对话里说"雇一个对测试很刻薄的评审机器人"就能做到，面板下一次刷新就会出现。

## 数据位置

- 名册：`$DSH_HOME/bots-team/team.json`（默认 `~/.dsh/bots-team/team.json`）。
- 机器人文件夹：`$DSH_HOME/bots-team/bots/<bot-id>/`，每个含 `AGENTS.md` 与 `.git` 指令根标记。
- 面板通过回环接口 `/bots-team/api` 与 Host 半通信。

删除机器人只把它移出名册；文件夹、文件、会话都保留，所以删除是可恢复的。

## 结构

| 文件 | 作用 |
|---|---|
| [`index.js`](index.js) | Host 半：名册存储、机器人文件夹与 `AGENTS.md`、`/bots-team/api`、代理工具。 |
| [`client.js`](client.js) | 浏览器半：`sidebar.panellist` 入口与 `main` 面板，一个 `__ModuleLoader__` 工厂。 |
| [`cordis.patch.yml`](cordis.patch.yml) | 插入 Host 行的 bundle 补丁。 |
| [`locale/`](locale) | 插件管理器的标题、描述与详情文档路径。 |
| [`docs/DETAIL.md`](docs/DETAIL.md) | 插件管理器里展示的说明页。 |
| [`test/smoke.mjs`](test/smoke.mjs) | 覆盖两半的 24 项检查，不需要浏览器。 |

Host 半只 import Node 内置模块，所以无论装进哪个 profile 都能解析；浏览器半除 React 外不 import 任何东西。

## 开发

```sh
node test/smoke.mjs      # 全部检查；失败时退出码非 0
```

测试用假 Node 请求对驱动真实注册的路由，在临时数据目录里跑 create/update/bind/delete 与四个工具，然后用 `__ModuleLoader__` 桩和一个小 React shim 加载 `client.js`，运行真实面板组件并检查输出树。它覆盖契约与数据流，不覆盖像素。

## 限制

- 面板依赖 Host 半；若某个桌面壳从 `file://` 提供页面，则无法访问回环接口，面板会明确提示。
- 一个 profile 一份名册；机器人不按项目隔离。
- 一个机器人一个对话。想重来就换一个新机器人；会话分叉仍在会话列表里做。
- 机器人继承 profile 的模型，尚未实现每机器人独立选模型。
- 删除机器人不会归档它的会话，会话仍在会话列表里。
