# DSH Bot Team

常驻在 [DeepSeek Harness](https://github.com/deepseek-ai) 左侧栏里的 AI 协作团队。

每个 Bot 都是一个真实的 DSH Session：拥有独立人设、专属产出目录，以及点开即聊的长期对话。整支团队共用一个工作区，侧栏呈现为清晰的通讯录，而不是一堆「未命名」对话。

## 为什么做这个？

DSH 本身运行 Agent 已经很顺手，但缺少一个**集中管理常用角色**的入口。这个插件补上的是**长期身份与条理性**：为每个 Bot 固定名称、图标和分工，绑定专属目录，把常用角色变成一键直达的长期对话。

名册内置一位**参谋长**：负责把你的需求拆解、指派给合适的成员并提交派单建议。它自己不直接执行任务，且**没有你的点击，不会发出任何消息**。

面板不是独立的运行时，而是架在原生 DSH Session 之上的聊天界面。在这里发消息底层调用 `session.prompt()` —— 与主输入框走同一链路 —— 回复会同步流向当前面板与该 Bot 的原生 Session。需要精细操作时，点击 **打开完整对话** 即可切回完整的 DSH 工作区（查看工具调用、审批权限、读写文件或使用终端）。

## 实现原理：一个工作区，每个 Session 一个人设

整支团队共用**一个工作区**（即名册所在目录），侧栏只显示一个分组，每个 Bot 对应一条以自己命名的对话。具体机制如下：

* **按 Session 注入人设** —— 后端贡献一段系统 Prompt，注入时识别当前 Session 属于哪个 Bot；其他 Session 读到的是空字符串，避免人设串味。
* **纯文本持久化** —— 同一份指令同步写入 `<Bot目录>/AGENTS.md`，方便在本地查看、编辑和做 `git diff`。
* **产出文件隔离** —— 每个 Bot 拥有独立的 `bots/<id>/` 目录存放产出文件，人设中会明确告知该路径。

## 派单是怎么走的

参谋长就是派单的人：你对它说一次，活就出去了。

1. 参谋长调用 `team_assign`，为每个目标 Bot 记录一条派单。因为这个调用来自参谋长，它会**立即投递**——工具返回 `dispatched`，任务作为一条标注来源的用户消息进入目标 Bot 的 Session。
2. 目标 Bot 恢复空闲时，该派单自动结清，面板给出提示。

**其他任何会话**（这个聊天窗口、另一个窗口、子代理）都不是参谋长，它们的 `team_assign` 只会**记录建议**：团队面板把它列进队列，侧栏图标显示数量角标，并有一个跨面板的小悬浮条跟随。你点单条**派发**或**全部派发**，它才真正发出去。

你也可以自己对某个 Bot 派单：选中它，点**派单**，写好任务发出。

若某条派单无法启动（通常是该 Bot 尚未建立 Session），它会**留在队列中并注明原因**，附带**重试**按钮，不会静默消失。

**无人值守模式**（`unattended: true`）把这个口子开得更大：任何调用方都直接投递，不只是参谋长。面板上会显示当前模式，一眼可知现在按哪种规则走。

## 核心特性

* **侧边栏直达** —— 在左侧边栏新增全局 **团队** 入口（两个对话气泡，右上角一颗小星代表参谋长），点击即可在主视图打开名册。
* **自带参谋长** —— 内置 Bot，固定在名册首位，负责拆解需求并提出派单建议。即使误删，下次启动也会自动雇回来；旧对话仍留在 DSH 的会话列表里，新的参谋长从新对话开始。
* **参谋长直派，其他会话只提议** —— 参谋长的 `team_assign` 按你的要求直接发出；其他会话只能留下建议，面板角标计数，等你点派发。
* **侧栏具名展示** —— 所有 Bot 对话统一归入 **Bot team** 工作区，每条以 Bot 命名，告别「未分组」下的一堆「未命名」。
* **实时成员列表** —— 展示头像、名称、分工与实时的“工作中 / 空闲”状态；面板打开时自动刷新，在其他窗口或对话中新雇的 Bot 会自动出现。
* **内嵌轻量聊天** —— 对话流以真实元素渲染 Markdown（标题、列表、表格、代码块、引用、链接）而非注入 HTML；提供工具调用标签、实时状态指示，输入框直连底层原生 DSH Session。
* **按需延迟启动** —— 发出第一条消息时才在团队工作区中创建 Session，并以 Bot 名称命名，无需提前手动建目录。
* **内置角色模板** —— 预置 **Scout**（调研）、**Forge**（开发）、**Ledger**（分析）、**Quill**（写作）四类模板；首次启动默认配好前三位成员。
* **一键重开** —— 归档该 Bot 当前对话并解除绑定，下一条消息会在团队工作区中开启新 Session；旧对话保留在会话归档中，随时可恢复。
* **支持对话式管理** —— 内置 Agent 工具，可在任意 DSH 聊天窗口中用自然语言雇佣、调整或解雇 Bot。
* **适配深浅色主题** —— 所有颜色均取自 DSH 主题 token，浅色与深色模式下均清晰可读。
* **整队列批量派发** —— **全部派发**一键发出所有待确认建议；失败条目留在原位，注明原因并提供**重试**按钮。
* **中英双语界面** —— 支持简体中文与英文，自动跟随 DSH 客户端语言切换。

## 组队参考方案

无需从零设计分工。以下两套配置可直接套用，跑顺后再按习惯微调：

**科研审稿组** —— 输入论文或实验方案，输出有理有据的评估：

| 成员 | 分工 | 可直接复制的人设指令（Prompt） |
| --- | --- | --- |
| Reviewer | 审稿人 | 扮演严厉但公正的审稿人：核心结论有充分的数据支撑吗？对比基线公平吗？什么样的实验结果能证伪它？ |
| Replicator | 实验复现 | 在当前目录下用现有数据重跑论文方法，明确汇报哪些结果成功复现、哪些对不上，并附上验证所用的终端命令。 |
| Librarian | 文献调研 | 检索相关研究并通读全文，输出带原文链接的精简简报：有哪些新意、学界争议点在哪、下一步最值得精读哪篇。 |

**研发交付组** —— 负责代码实现与线上排障：

| 成员 | 分工 | 可直接复制的人设指令（Prompt） |
| --- | --- | --- |
| Builder | 开发实现 | 编写最小可用的代码改动，实际跑通验证，并附上能证明改动生效的那条测试或运行命令。 |
| Reviewer | 代码审查 | 合入前严格审查 Diff：检查逻辑正确性、指出本可提前拦住隐患的单元测试，以及任何可能破坏下游调用方的地方。 |
| Operator | 运维排障 | 盯紧正在运行的服务，根据日志定位并复现故障，最终交回修复方案或精准的根因定位报告。 |

你可以在面板中手动创建（点击 **新建机器人**，填写角色并粘贴人设），也可以直接在任意聊天框里输入：*“帮我雇一个挑剔的审稿 Bot，再配一个只输出带链接简报的文献调研 Bot。”* 名称、图标和头衔均可自定义 —— 真正决定行为的是人设指令，且随时可改。

## 安装指南

**环境要求：** DSH `0.2.x` 及以上版本，并已启用 Web 界面。

1. 克隆仓库到本地：
   ```sh
   git clone https://github.com/BaiGang/dsh-bots-team.git
   ```
2. 在 DSH 中进入 **插件 → 添加插件**，选择克隆下来的目录。
3. 刷新浏览器页面以加载前端包，左侧边栏将出现 **团队** 图标。

### 可选配置

可在插件配置中自定义数据目录与派单行为：

```yaml
- id: bots-team
  name: 'dsh-bots-team'
  config:
    dataDir: /absolute/path/to/team-data   # 默认路径：$DSH_HOME/bots-team
    unattended: false                      # 设 true 才允许无点击投递
    guidance: true                         # 在每个 Session 的系统 Prompt 里加一段「团队」说明
```

## 快速上手

1. 点击左侧边栏的 **团队** 图标。
2. 选择一个预置成员，或点击 **+ 新建机器人** 从模板创建。
3. 直接发消息开聊。首条消息会在团队工作区中打开该 Bot 的 Session，后续对话沿用同一上下文。
4. 需要查看完整细节时，随时点击 **打开完整对话** 切回 DSH 主会话界面。
5. 点击 **编辑** 可修改名称、图标、角色或人设指令（同步写入 `AGENTS.md`，下一轮回复生效）。
6. 在同一编辑界面点击 **开始新对话**，可归档当前 Session 并让 Bot 从干净状态重新开始 —— 旧对话不会被删除。

## Agent 管理工具

DSH 中的任意 Agent 都可通过以下内置工具查看或管理团队：

| 工具名 | 功能说明 |
| --- | --- |
| `team_roster` | 列出所有成员的角色、人设指令、目录路径及当前 Session 状态。 |
| `team_hire` | 招募新成员（指定名称、角色、人设、图标）并初始化其工作目录。 |
| `team_brief` | 更新现有成员的人设指令或角色分工。 |
| `team_fire` | 将成员移出名册（其工作目录与历史 Session 仍保留在本地磁盘）。 |
| `team_assign` | 为指定 Bot 记录派单。仅在无人值守模式下直接投递，否则等待面板确认。 |
| `team_status` | 汇报每个 Bot 的 Session、Agent 是否在线运行，以及最近派单的状态。 |

> **用法示例：** 在任意 DSH 聊天窗口中输入 *“帮我招一个对单元测试极其较真的代码审查机器人”* —— 下次刷新团队面板时，新成员即可就位。

## 数据存储与安全

* **成员清单：** `$DSH_HOME/bots-team/team.json`（默认 `~/.dsh/bots-team/team.json`），同时保存最近 100 条派单记录。
* **团队工作区：** 名册目录本身被注册为名为 **Bot team** 的工作区；每个 Bot 的对话都是其中的一条 Session，标题即 Bot 名称。
* **独立目录：** `$DSH_HOME/bots-team/bots/<bot-id>/`，每个目录下包含 `AGENTS.md` 与 `.git` 隔离标记。
* **通信方式：** 前端面板通过本地回环接口 `/bots-team/api` 与后端通信。

**安全移除机制：** 解雇或删除成员仅从 `team.json` 中移除记录，对应的工作目录、产出文件与底层 DSH Session 均完好保留在磁盘上，便于恢复。

## 本地开发与测试

运行冒烟测试：

```sh
node test/smoke.mjs      # 执行全部 60 项检查；任一失败返回非 0 退出码
```

测试脚本通过模拟 Node 请求/响应对象调用真实 handler（少数用例走不依赖传输的分发器），在临时目录中验证名册操作与全部六个 Agent 工具；随后通过 `__ModuleLoader__` 桩代码和轻量级 React 垫片加载 `client.js`，校验渲染输出与数据流 —— 全程无需真实浏览器。其中几条专门防范历史回归：旧快照不能复活已清空的 Session 绑定、人设不会泄漏到名册之外的 Session、品牌色填充的控件不得将文字颜色写死为白色。

## 已知限制

* **共用一个工作目录：** 所有 Bot Session 均运行在名册目录下；若某个 Bot 自行切换了工作目录，将脱离该分组。
* **依赖本地 HTTP 服务：** 桌面端外壳若通过 `file://` 协议加载页面，前端无法访问 `/bots-team/api`（面板会给出明确提示）。
* **按 Profile 共享：** 名册绑定在当前 DSH Profile 下全局共享，暂不支持按项目（Project）隔离。
* **单成员单 Session：** 每个 Bot 对应一条连续对话；点击 **开始新对话** 会归档旧 Session 并开启新对话。需要分叉（Fork）时，仍需在 DSH 主会话列表中操作。
* **跟随全局模型：** 所有成员继承当前 Profile 的模型配置，暂不支持为单个 Bot 单独指定模型。
* **解雇不归档：** 移出成员不会删除或归档其 Session；仅 **开始新对话** 会执行归档，且归档可恢复。
* **老对话留在原地：** 共享工作区之前创建的 Session 保留原有工作目录，无法并入该分组。
* **派单前需先有 Session：** 面板会在首次派单时自动创建并绑定；若创建失败，队列会保留该条目、注明原因并提供**重试**按钮。
* **完成状态靠轮询而非推送：** 面板在下一次刷新时检测到派单完成并给出简短提示，目前尚无面板之外的通知。
