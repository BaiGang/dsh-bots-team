# DSH Bot Team

常驻在 [DeepSeek Harness](https://github.com/deepseek-ai) 左侧栏里的 AI 协作团队。

每个 Bot 都是一个真实的 DSH 会话（Session），拥有独立的工作目录、人设指令和长期对话记录 —— 需要时像在通讯录里找同事一样点开就能聊，不用再去历史会话列表里大海捞针。

[English](README.md) | **中文**

```
┌ 你的机器人团队 ─────────────────────── [ + 新建机器人 ] ┐
│ 🧭 Scout        │  🧭 Scout · Researcher   ● 空闲      │
│    Researcher   │  ┌ 对话记录 ─────────────────────┐  │
│ 🛠️ Forge        │  │                               │  │
│    Builder      │  └───────────────────────────────┘  │
│ 📊 Ledger       │  [ 给 Scout 发消息… ]        [发送]   │
└─────────────────────────────────────────────────────────┘
```

## 为什么做这个？

DSH 本身跑 Agent 已经很强了，但缺一个**固定管人**的地方。这个插件补上的是**长期身份与条理性**：给每个 Bot 固定的名字、图标和分工，绑定专属的工作目录，把常用角色变成一键直达的长期对话。

这个面板并不是另一套独立的运行时，而是架在原生 DSH 会话之上的聊天界面。在这里发消息底层调用的就是 `session.prompt()` —— 和主聊天框走完全相同的链路 —— 所以回复会同时流向当前面板和该 Bot 的原生会话。遇到需要精细操作的场景，点一下 **打开完整对话**，就能立刻切回完整的 DSH 工作区（查看工具调用、审批权限、读写文件或操作终端）。

## 实现原理：目录即人设

创建 Bot 时，后端会直接把人设指令写入 `<Bot目录>/AGENTS.md`。由于 DSH 原生的工作区加载器会在启动会话时自动读取所在目录的 `AGENTS.md`，这套机制天然带来了三个好处：

- **无需魔改提示词** —— 人设走 DSH 官方支持的工作区指令机制加载，不搞脆弱的系统提示词注入。
- **纯文本持久化** —— 指令落盘保存，重启不丢，随时可以在本地直接查看、编辑或做 `git diff`。
- **干净的上下文隔离** —— 每个 Bot 目录内都带有一个 `.git` 根标记，防止上层父目录的 `AGENTS.md` 规则混入污染上下文。

## 核心特性

- **侧边栏直达** —— 在左侧边栏新增全局 **团队** 入口（双机器人图标），点击即可在主视图展开团队成员列表。
- **实时成员列表** —— 展示头像、名称、分工以及实时的“工作中 / 空闲”状态；面板打开期间会自动同步，在其他窗口或对话里新雇的 Bot 也会自动出现。
- **内嵌轻量聊天** —— 支持查看对话流、工具调用标签与运行状态，输入框直接连通底层原生 DSH 会话。
- **按需延迟启动** —— 只有发出第一条消息时，系统才会在该 Bot 的专属目录里初始化会话，确保开口前 `AGENTS.md` 指令已完整加载。
- **内置角色模板** —— 预置 **Scout**（调研）、**Forge**（开发）、**Ledger**（分析）、**Quill**（写作）四类模板；首次启动默认配好前三位成员。
- **支持对话式管理** —— 内置一组 Agent 工具，你可以在任意 DSH 聊天窗口里直接用自然语言雇佣、调教或解雇 Bot。
- **中英双语界面** —— 完整支持简体中文与英文，自动跟随 DSH 客户端语言切换。

## 组队参考方案

不用从零开始琢磨怎么搭班子。下面这两套分工可以直接拿去用，跑顺了再按自己的习惯微调：

**科研审稿组** —— 丢进去一篇论文或实验方案，拿回有理有据的评估：

| 成员 | 分工 | 可直接复制的人设指令（Prompt） |
|---|---|---|
| Reviewer | 审稿人 | 扮演严厉但公正的审稿人：核心结论有充分的数据支撑吗？对比基线公平吗？什么样的实验结果能证伪它？ |
| Replicator | 实验复现 | 在当前目录下用现有数据重跑论文方法，明确汇报哪些结果成功复现、哪些对不上，并附上验证所用的终端命令。 |
| Librarian | 文献调研 | 检索相关研究并通读全文，输出带原文链接的精简简报：有哪些新意、学界争议点在哪、下一步最值得精读哪篇。 |

**研发交付组** —— 盯紧代码实现与线上排障：

| 成员 | 分工 | 可直接复制的人设指令（Prompt） |
|---|---|---|
| Builder | 开发实现 | 编写最小可用的代码改动，实际跑通验证，并附上能证明改动生效的那条测试或运行命令。 |
| Reviewer | 代码审查 | 合入前严格审查 diff：检查逻辑正确性、指出本可提前拦住隐患的单元测试，以及任何可能破坏下游调用方的地方。 |
| Operator | 运维排障 | 盯紧正在运行的服务，根据日志定位并复现故障，最终交回修复方案或精准的根因定位报告。 |

你可以在面板里手动创建（点 **新建机器人**，填好角色并粘贴人设），也可以直接在任意聊天框里吩咐一句：*“帮我雇一个挑剔的审稿 Bot，再配一个只输出带链接简报的文献调研 Bot。”* 名字、图标和头衔怎么起都行 —— 真正决定它怎么干活的是人设指令，而且随时能改。

## 安装指南

**环境要求：** DSH `0.2.x` 及以上版本，且已启用 Web 界面。

1. 克隆仓库到本地：

   ```sh
   git clone https://github.com/BaiGang/dsh-bots-team.git
   ```

2. 打开 DSH，依次进入 **插件 → 添加插件**，选择刚刚克隆下来的目录。
3. 刷新浏览器页面以加载前端插件包，左侧边栏就会出现 **团队** 图标。

### 可选配置

如需自定义数据存储路径，可在插件配置中指定 `dataDir`：

```yaml
- id: bots-team
  name: 'dsh-bots-team'
  config:
    dataDir: /absolute/path/to/team-data   # 默认路径：$DSH_HOME/bots-team
```

## 快速上手

1. 点击左侧边栏的 **团队** 图标。
2. 点选一个预置成员，或点击 **+ 新建机器人** 从模板创建。
3. 直接发消息开聊。首条消息会在该 Bot 的专属目录下创建会话，后续聊天自动接着同一上下文继续。
4. 需要看完整细节时，随时点击 **打开完整对话** 切回 DSH 主会话界面。
5. 点击 **编辑** 可随时修改名称、图标、角色或人设指令（修改后立即写入 `AGENTS.md`，下一轮回复即刻生效）。

## Agent 管理工具

DSH 里的任意 Agent 都可以通过以下内置工具查看或管理你的团队：

| 工具名 | 功能说明 |
|---|---|
| `team_roster` | 列出所有团队成员的角色、人设指令、目录路径及当前会话状态。 |
| `team_hire` | 招募新成员（指定名称、角色、人设、图标）并自动初始化工作目录。 |
| `team_brief` | 修改现有成员的人设指令或角色分工。 |
| `team_fire` | 将成员移出团队列表（其工作目录与历史会话仍保留在本地磁盘上）。 |

> **用法示例：** 在任意 DSH 聊天窗口里输入 *“帮我招一个对单元测试极其较真的代码审查机器人”* —— 下次刷新团队面板时，这位新同事就已经在岗了。

## 数据存储与安全

- **成员清单：** `$DSH_HOME/bots-team/team.json`（默认为 `~/.dsh/bots-team/team.json`）。
- **独立工作区：** `$DSH_HOME/bots-team/bots/<bot-id>/`，每个目录下均包含 `AGENTS.md` 与 `.git` 隔离标记。
- **通信方式：** 前端面板通过本地回环接口 `/bots-team/api` 与后端通信。

**安全移除机制：** 解雇或删除成员只会将其从 `team.json` 名单中剔除，对应的工作目录、产出文件以及底层 DSH 会话都会完好保留在硬盘上，防止误删丢稿。

## 目录结构

| 文件 / 目录 | 说明 |
|---|---|
| [`index.js`](index.js) | **后端逻辑（Host）：** 负责成员持久化、工作区与 `AGENTS.md` 初始化、`/bots-team/api` 接口及 Agent 工具注册。 |
| [`client.js`](client.js) | **前端界面（Browser）：** 通过单个 `__ModuleLoader__` 工厂函数注册侧边栏入口（`sidebar.panellist`）与主面板（`main`）。 |
| [`cordis.patch.yml`](cordis.patch.yml) | 用于向宿主注入后端插件配置的补丁文件。 |
| [`locale/`](locale) | 插件多语言文案（插件名称、简介及详情文档路径）。 |
| [`docs/DETAIL.md`](docs/DETAIL.md) | 在 DSH 插件管理器内展示的详细介绍页。 |
| [`assets/`](assets) | 插件市场预览图及用于生成预览图的 SVG 源文件。 |
| [`test/smoke.mjs`](test/smoke.mjs) | 端到端冒烟测试（共 24 项断言，同时覆盖前后端逻辑，无需启动浏览器）。 |

**零第三方依赖：** 后端仅使用 Node.js 原生内置模块，装进任何 DSH 环境都能直接跑；前端仅从 DSH 运行时模块表中引用 React。

## 本地开发与测试

运行冒烟测试：

```sh
node test/smoke.mjs      # 执行全部 24 项检查；任一失败返回非 0 退出码
```

测试脚本通过构造模拟的 Node 请求/响应对象直接调用 HTTP 路由，在临时目录中完整跑通增删改查与四个 Agent 工具；随后利用 `__ModuleLoader__` 桩代码和轻量级 React 垫片加载 `client.js`，直接校验组件树渲染与数据流 —— 全程无需拉起真实浏览器。

## 已知限制

- **依赖本地 HTTP 服务：** 如果桌面端外壳直接通过 `file://` 协议加载页面，前端将无法请求 `/bots-team/api` 接口（此时面板会给出明确提示）。
- **按 Profile 共享：** 团队列表绑定在当前 DSH Profile 下全局共享，暂不支持按项目（Project）维度隔离。
- **单成员单会话：** 每个 Bot 固定对应一条连续对话流。如果想彻底清空重来，需要新建一个 Bot；如需从某处分叉对话（Fork），仍需回到 DSH 主会话列表中操作。
- **跟随全局模型：** 所有成员默认继承当前 Profile 配置的模型，暂不支持为单个 Bot 独立指定不同模型。
- **底层会话需手动归档：** 将成员移出团队不会同步删除或归档它在 DSH 主会话列表中的历史记录。
