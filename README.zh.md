# DSH Bot Team

在 [DeepSeek Harness](https://github.com/deepseek-ai) 左侧栏里，一支长期在线的 AI 机器人团队。

每个机器人都是一个真实的 DSH 会话，背后有自己的工作文件夹、人格设定与对话历史 —— 像给联系人列表里的同事发消息一样和它说话，而不是在会话记录里翻找。

[English](README.md) | **中文**

```
┌ 你的机器人团队 ─────────────────────── [ + 新建机器人 ] ┐
│ 🧭 Scout        │  🧭 Scout · Researcher   ● 空闲      │
│    Researcher   │  ┌ 对话记录 ─────────────────────┐  │
│ 🛠️ Forge        │  │                               │  │
│    Builder      │  └───────────────────────────────┘  │
│ 📊 Ledger       │  [ 给 Scout 发消息… ]        [发送]   │
└─────────────────────────────────────────────────────────┘
```

## 为什么？

DSH 本来就很会跑 agent。消息式名册补上的是**持续性与组织性**：每个机器人有稳定的身份（名字、图标、角色）、专属的工作文件夹，以及一键可达的长期对话。

面板是架在原生 DSH 会话之上的消息界面，而不是另一套运行时。在这里发消息调用的是 `session.prompt()` —— 和主输入框完全同一条路径 —— 所以回复会同时流进这个面板和机器人自己的原生会话。需要更强的控制力时，点 **打开完整对话** 就回到完整 DSH 工作区（工具、审批、文件、终端）。

## 工作原理：文件夹即人格

创建机器人时，宿主后端把它的指令直接写进 `<机器人文件夹>/AGENTS.md`。DSH 原生的 workspace loader 会为在该目录下启动的每个会话自动读取 `AGENTS.md`，因此：

- **不碰提示词 hack** —— 人格经由 DSH 原生的指令机制载入，而不是脆弱的系统提示词注入。
- **纯文本持久化** —— 指令重启不丢，并且可以直接在磁盘上读、改、做 diff。
- **干净的上下文隔离** —— 每个机器人文件夹都带一个 `.git` 根标记，上层目录的 `AGENTS.md` 指令不会渗进来。

## 功能

- **侧栏集成** —— 在左侧栏加入全局 **团队** 图标（两个机器人头像），并在主栏打开名册视图。
- **实时名册** —— 显示每个机器人的头像、名字、角色与实时的工作/空闲状态；面板打开时自动刷新，别处（另一个窗口或对话中）雇来的机器人也会自动出现。
- **内嵌对话** —— 包含对话记录、工具调用小标签、实时状态指示，以及一个直接接到底层 DSH 会话的输入框。
- **会话懒启动** —— 机器人的会话在它收到第一条消息时才在其专属文件夹里创建，确保 `AGENTS.md` 指令在它开口前已载入。
- **内置角色模板** —— 自带 **Scout**（研究员）、**Forge**（工程师）、**Ledger**（分析师）、**Quill**（写作者）；首次启动会预先雇好三个。
- **可被代理管理** —— 内置代理工具，任意 DSH 对话都能用自然语言雇佣、改写或解雇机器人。
- **双语界面** —— 支持英文与简体中文，自动跟随你的 DSH 界面语言。

## 团队配方

不必从零设计名册。下面两个组合直接可用，聊过一轮之后再按需改成自己的。

**研究桌** —— 输入一篇论文或一个实验，输出一个有依据的判断：

| 机器人 | 角色 | 可以直接粘的人格 |
|---|---|---|
| Reviewer | 审稿人 | 像一个严厉但公正的审稿人：结论有证据支撑吗？基线公平吗？什么结果能证伪它？ |
| Replicator | 实验复现 | 在你的文件夹里用现有数据重跑方法，明确说明哪些复现了、哪些没有，并给出能证明它的命令。 |
| Librarian | 论文检索 | 找相关工作、读掉它、返回带链接的短简报：什么新、哪里有争议、接下来该读什么。 |

**交付桌** —— 代码与运维：

| 机器人 | 角色 | 可以直接粘的人格 |
|---|---|---|
| Builder | 实现 | 写最小的可用改动，跑起来，并报告能证明它的那条命令。 |
| Reviewer | 评审 | 上线前读 diff：正确性、本可提前抓住这个 bug 的测试、任何会破坏调用方的地方。 |
| Operator | 运维 | 盯着正在跑的东西，从日志复现故障，交回一个修复或一个精确的问题。 |

在面板里建（**新建机器人**，填角色和人设），或者直接在对话里说：*“雇一个像严厉审稿人那样读稿的机器人，再雇一个只返回带链接简报的文献机器人。”* 名字、图标、角色都随你 —— 真正被遵循的是人格，而人格随时可以重写。

## 安装

**前置条件：** DSH `0.2.x` 或更高版本，并启用 Web 界面。

1. 克隆本仓库：

   ```sh
   git clone https://github.com/BaiGang/dsh-bots-team.git
   ```

2. 在 DSH 中打开 **插件 → 添加插件**，选择克隆下来的目录。
3. 刷新浏览器页面，让客户端 bundle 进入启动图。左侧栏就会出现 **团队**。

### 配置（可选）

可以在插件配置里自定义存储目录：

```yaml
- id: bots-team
  name: 'dsh-bots-team'
  config:
    dataDir: /absolute/path/to/team-data   # 默认：$DSH_HOME/bots-team
```

## 快速开始

1. 点左侧栏的 **团队**。
2. 选一个预置机器人，或点 **+ 新建机器人** 从模板创建一个。
3. 发一条消息。第一条消息会在它的文件夹里初始化会话；之后的消息继续同一个线程。
4. 随时点 **打开完整对话**，在主栏跳到完整的 DSH 会话视图。
5. 点 **编辑** 可以改名字、图标、角色或指令（`AGENTS.md` 立即更新，下一条消息生效）。

## 代理工具

DSH 里的其他代理可以检查并管理你的名册：

| 工具 | 说明 |
|---|---|
| `team_roster` | 列出所有机器人的角色、人格、文件夹路径与会话状态。 |
| `team_hire` | 新建一个机器人（名字、角色、人格、图标）并初始化它的工作文件夹。 |
| `team_brief` | 更新某个机器人的人格指令或角色。 |
| `team_fire` | 把机器人移出名册，文件夹与会话原样保留在磁盘上。 |

> **示例：** 对任意 DSH 对话说 *“雇一个对单元测试很苛刻的评审机器人”* —— 新机器人会在团队面板下一次刷新时出现。

## 数据与存储

- **名册清单：** `$DSH_HOME/bots-team/team.json`（默认 `~/.dsh/bots-team/team.json`）。
- **机器人工作区：** `$DSH_HOME/bots-team/bots/<bot-id>/`，每个含 `AGENTS.md` 与 `.git` 根标记。
- **接口传输：** 浏览器面板通过回环接口 `/bots-team/api` 与宿主后端通信。

**安全删除：** 解雇或删除机器人只会移除它在 `team.json` 里的条目；它的工作文件夹、文件与 DSH 会话都原样留在磁盘上，随时可以恢复。

## 项目结构

| 路径 | 作用 |
|---|---|
| [`index.js`](index.js) | **宿主后端：** 名册存储、工作区与 `AGENTS.md` 供给、`/bots-team/api` 路由、代理工具。 |
| [`client.js`](client.js) | **浏览器客户端：** 通过一个 `__ModuleLoader__` 工厂注册 `sidebar.panellist` 图标与 `main` 面板。 |
| [`cordis.patch.yml`](cordis.patch.yml) | 注册宿主插件行的 bundle 补丁。 |
| [`locale/`](locale) | 本地化的插件元数据（标题、描述与详情文档路径）。 |
| [`docs/DETAIL.md`](docs/DETAIL.md) | 插件管理器里展示的插件说明。 |
| [`assets/`](assets) | 插件市场用的展示图，以及渲染它所用的构图 SVG。 |
| [`test/smoke.mjs`](test/smoke.mjs) | 无浏览器测试套件（24 项检查，覆盖宿主与客户端两侧）。 |

**零外部依赖：** 宿主后端只用 Node.js 内置模块，因此在任何 DSH profile 里都能干净运行；浏览器客户端只从 DSH 的运行时模块表里引入 React。

## 开发

运行冒烟测试套件：

```sh
node test/smoke.mjs      # 运行 24 项检查；失败时退出码非 0
```

测试用模拟的 Node 请求/响应对驱动 HTTP 路由，在临时目录里验证增删改查与四个代理工具，再用 `__ModuleLoader__` 桩和轻量 React shim 加载 `client.js`，断言组件树与数据流 —— 全程不需要浏览器。

## 已知限制

- **需要 HTTP 回环：** 通过 `file://` 提供界面的桌面壳无法访问 `/bots-team/api`（面板会在这种环境下明确提示）。
- **只作用于单个 profile：** 一份名册由当前 DSH profile 共享，而不是按项目隔离。
- **每个机器人单线程：** 每个机器人维持一段连续对话。想重新开始需要另雇一个机器人，而对话分叉要在主会话列表里做。
- **共用模型配置：** 机器人继承当前 profile 的模型，暂不支持每机器人独立选模型。
- **会话需手动清理：** 把机器人移出名册不会删除或归档它在 DSH 主会话列表里的底层会话。
